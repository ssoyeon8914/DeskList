기준 문서: `docs/To_do_list_2.2.xlsx`  
제약: 배포·출시 제외 · UI 밤티 방지 · 코드 낭비 최소화  
스킬 라우팅: `.cursor/skills/todo-workflow`

---

## 1. 목표

엑셀 템플릿의 **핵심 루프**를 웹 앱으로 재현한다.

> 할일 입력 → (표시·상태 자동 계산) → 월간 달력에 날짜별 반영 → (선택) 필터·통계

엑셀 피벗/슬라이서/장식 요소는 **복제하지 않고** 앱 상태·쿼리로 대체한다.

## 2. 범위

### 2.1 MVP (P0) — 반드시 구현

| 기능 | Excel 대응 | 완료 조건 |
|------|------------|-----------|
| 구분·아이콘 설정 | 세팅 | 일정/할일/회의 등 CRUD + 아이콘 |
| 할일 CRUD + 진행률 바 | 할일표 | 표 입력, 표시·상태 파생, 바 UI |
| 달력 연/월/시작일 | 달력 우측 패널 | 그리드·주 헤더 재정렬 |
| 달력 투영 | 달력 셀 | 아이콘·표시·업무·진행률 |
| 오늘/주말 헤더 | 조건부 서식 | SUN/SAT 색, 오늘 강조 |

**MVP 성공 기준:** 할일 저장 → 달력 해당 칸 반영 + 연·월·시작일 조작 가능.

### 2.2 확장 (P1)

| 기능 | Excel 대응 |
|------|------------|
| 할일 대시보드 KPI·완료율·우선순위 바 | 할일 상단 |
| 슬라이서 (날짜·구분·우선순위·카테고리·상태) | 슬라이서 |
| Note + Check List | 우측 위젯 |
| 만다라트 9×9 + 미러 동기화 | 만다라트 |

### 2.3 후순위 (P2)

| 기능 | 비고 |
|------|------|
| 엑셀형 도움말 패널 | 웹 안내로 축소 가능 |

### 2.4 비범위 (명시적 제외)

- 배포, 호스팅, CI 출시, 스토어 등록
- 엑셀 피벗 시트 UI·배열수식 엔진 이식
- RAND 장식 그래픽, 시트 보호 UX
- 멀티유저·실시간 협업 (요청 전까지)

> 범위가 흔들리면 `todo-office-hours`로 In/Out을 다시 고정한 뒤 진행한다.

## 3. 진행 원칙

1. **목업 우선:** 정적 HTML(`mockups/`)로 디자인·기능 기획을 다듬은 뒤 본구현. 목업 합의 전 React 앱·스토어 본구현 금지.
2. **IA:** 달력 / 할일 / 설정 **분리 페이지** (공통 상단 네비). 본구현 라우트도 동일.
3. **단일 소스:** 할일 저장소 하나. 달력·통계는 파생 뷰.
4. **파생은 한곳:** `표시`, `상태` 계산 헬퍼 공유. UI마다 복제 금지.
5. **피벗 대체:** 필터 상태 객체 + 집계 함수.
6. **UI:** 목업 토큰 → `DESIGN.md` 승격 후 본구현. 밤티(보라 그라데이션·카드 대시보드 등) 금지.
7. **티켓 단위 수직 슬라이스:** “레이어만 깔기”보다 “입력→달력 반영”이 한 티켓에 끝나게.
8. **검증:** 기능은 `todo-qa-only`로 리포트 → 버그는 `todo-investigate` → UI는 `todo-design-review`.

## 4. 단계별 계획

### Phase 0 — 목업으로 기획 확정 (본구현 전)

| 순서 | 작업 | 산출물 |
|------|------|--------|
| 0a | 목업 브리프 + 초안 디자인 토큰 | `docs/mockup-brief.md`, `mockups/css/tokens.css`, `DESIGN.md` 초안 |
| 0b | 정적 목업 3페이지 + 리뷰 루프 | `mockups/index.html`, `calendar.html`, `todos.html`, `settings.html` |
| 0c | 피드백으로 범위·디자인 확정 | `docs/mockup-notes.md`, `docs/mvp-scope.md`, `DESIGN.md` 확정 |
| 0d | 아키텍처·티켓 잠금 | `docs/eng-plan.md`, `todo-spec` 티켓 |

**게이트:** 목업 리뷰 합의(`mockup-notes` 결정란) + `mvp-scope` + `DESIGN.md` + `eng-plan` 없이 Phase 1 진입하지 않음.  
**목업 IA:** 공통 네비로 `달력 | 할일 | 만다라트 | 설정` 이동. 달력은 우측 연/월/시작일, 할일은 상단 대시보드 포함.

**기술 스택 결정 (0d eng-plan에서 확정):**

권장 기본안(변경 가능):

| 항목 | 권장 | 이유 |
|------|------|------|
| UI | React + Vite + TypeScript | 달력·리스트 상태 표현에 적합, 낭비 적은 구성 |
| 스타일 | CSS 변수 (`DESIGN.md` 토큰) | 목업 토큰 1:1 이전, 무거운 UI 키트 지양 |
| 상태/저장 | 로컬 우선 (예: 메모리 + `localStorage`) | 배포 없이 완결; 서버는 요청 시 추가 |
| 날짜 | 경량 유틸 (네이티브 `Date` 또는 dayjs 수준) | 월 그리드·요일만 필요 |
| 라우팅 | `/`(달력), `/todos`, `/mandalart`, `/settings` | 엑셀 시트 1:1 |

## 5. 권장 모듈 구조 (낭비 최소화)

```
src/
  domain/           # 타입, 파생 헬퍼, 순수 월그리드 계산
  data/             # repository (localStorage)
  features/
    settings/
    todos/
    calendar/
    filters/        # P1
    stats/          # P1
    mandalart/      # P2
  ui/               # 토큰·공통 프리미티브만
  app/              # 쉘, 라우트
```

의존 방향: `features/*` → `domain` / `data` → (순수).  
달력이 todos를 **복사 저장하지 않음**.

## 6. 데이터 흐름

```
                   ├─► TodoStore (CRUD + persist)
Todos 입력 ────────┘         │
                             ├─► derive(표시, 상태)
                             ├─► FilterState ──► filteredTodos
                             │                      ├─► CalendarView
                             │                      └─► StatsView

```

## 7. 품질·검증 계획

| 시점 | 방법 |
|------|------|
| 헬퍼·월그리드 | 순수 함수 픽스처 테스트 |
| MVP / P1 완료 시 | `todo-qa-only` 체크리스트 (스킬 내 매트릭스) |
| 버그 | `todo-investigate` (원인 문서화 후 수정) |
| UI 안정화 후 | `todo-design-review` |

QA 필수 시나리오 요약:

1. 생성 → 달력 당일 표시  
2. 날짜 변경 → 칸 이동  
3. 우선순위·진행률 → 표시·상태 일치  
4. 구분 아이콘 매핑  
5. (P1) 필터와 통계 일치  
6. 동일 날짜 N개 초과 시 overflow

## 8. 일정 가이드 (상대)

절대 날짜보다 **게이트**로 관리한다.

| 구간 | 내용 | 대략 비중 |
|------|------|-----------|
| Phase 0a–0b | 목업 구현·디자인 반복 | 전체의 20–25% |
| Phase 0c–0d | 범위·DESIGN·eng 확정 | 10–15% |
| Phase 1 | 코어·설정·저장 | 10–15% |
| Phase 2 | 할일+달력 MVP | 30–35% |
| Phase 3 | 필터·통계 | 15–20% |
| Phase 4 | 폴리시·P2 | 잔여 |

목업에서 IA·셀 밀도·진입점을 합의한 뒤 본구현. 파생·달력 없이 폼만 오래 유지하는 낭비 방지.
