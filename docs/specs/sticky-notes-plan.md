# 작업 계획서 · 스티커 메모

**목적:** 스티커 메모처럼 **짧은 정보를 자유롭게 적어 두는** 화면을 DeskList에 추가한다.  
**성격:** post-MVP · **목업 먼저** → 컨펌 → React 패리티  
**관련:** 엑셀 「메모지」(다짐·명언·잡메모) · 기존 백로그 T14(선택 메모) 확장  
**비범위(이번 계획):** 배포, 서버 동기화, 할일/달력 자동 연동, 리치 텍스트, 미니 체크리스트(루틴)

---

## 1. 문제 · 성공 기준

| | |
|--|--|
| **지금** | 할일·달력·만다라트·설정만 있음. “오늘 챙길 말”, 명언, 임시 메모를 둘 곳이 없음 |
| **성공** | 상단 네비에서 **메모**로 들어가, 스티커처럼 메모를 **추가·수정·삭제**하고 새로고침 후에도 유지된다 |
| **감성** | 표/폼이 아니라 **메모지 보드**로 읽힌다 (DeskList E+B 톤 유지, AI-슬롭 보드 지양) |

---

## 2. 제품 결정 (초안 · 확정 게이트에서 잠금)

### 2.1 In (v1)

- 상단 네비 5번째: **메모** (`/memos` · 목업 `memos.html`)
- 메모 단위 CRUD (본문 텍스트)
- **보드 레이아웃:** 여러 장 스티커가 한 화면에 보임
- 색 구분 소수(예: 3~4색) — 시각 스캔용
- localStorage 영속 · 샘플 seed 소수 · 설정「샘플 초기화」에 포함
- 삭제 확인은 `DLModal` (native confirm 금지)

### 2.2 Out (v1)

- 드래그 자유 배치 / 크기 조절 (좌표 저장) — **v1.1 후보**
- 마크다운·이미지·체크리스트 본문
- 할일·달력·만다라트와 양방향 연동
- 폴더 마스터·검색·공유·핀 고정(필요 시 v1.1) — **카테고리 칩 필터는 v1에 포함**
- 실시간 협업·클라우드

### 2.3 열어 둘 질문 (목업 전 짧게 확정)

1. **배치:** 고정 그리드(wrapping) vs 나중에 드래그?
2. **한 장 용량:** 짧은 메모(예: 200자) vs 긴 글(예: 2,000자)?
3. **네비 라벨:** `메모` / `메모지` / `스티키` 중?

**확정 (2026-09-22):** 그리드 wrapping · 본문 최대 3,000자 · 라벨 **메모**. 드래그는 v1.1.

## 3. 데이터 모델 (초안)

할일 스토어와 **독립** (만다라트와 같은 급).

```ts
type Memo = {
  id: string;
  title: string;         // 짧은 제목
  category: string;      // 자유 텍스트 · 기본 "일반" · 칩 필터용
  body: string;          // 본문 (최대 3,000자)
  color: MemoColor;      // "cream" | "mint" | "sky" | "rose"
  width?: number;        // px · 카드 resize
  height?: number;
  updatedAt: string;     // ISO
};

// AppState에 memos: Memo[]
```

| 항목 | 규칙 |
|------|------|
| 소스 오브 트루스 | `state.memos` |
| 파생 | 없음 (달력/KPI와 무관) |
| 영속 | 기존 desklist 키에 `memos` 병합 · 로드 시 없으면 `[]` 또는 seed |
| 초기화 | `resetSeed` 시 샘플 메모 포함 |

## 4. UX 스케치

```
[ DeskList ]  달력 · 할일 · 만다라트 · 메모 · 설정
─────────────────────────────────────────────
메모                          [ + 메모 추가 ]
스티커처럼 짧게 적어 두는 보드입니다.

┌────────┐ ┌────────┐ ┌────────┐
│ cream  │ │ mint   │ │ sky    │
│ 본문…  │ │ 본문…  │ │ 본문…  │
│     ✎🗑│ │     ✎🗑│ │     ✎🗑│
└────────┘ └────────┘ └────────┘
```

- **추가:** `+ 메모 추가` → 빈 스티커 생성 후 포커스(또는 인라인 편집)
- **수정:** 클릭/포커스로 본문 편집 · blur 또는 명시 저장(목업에서 한 방식으로 통일)
- **색:** 스티커 하단/코너 스와치 소수
- **빈 상태:** “첫 메모를 남겨 보세요” + CTA
- **모션:** 등장 1종 정도만 (과한 날림/기울기 스택 금지)

## 5. 작업 순서 (목업 우선)

| 단계 | 작업 | 산출 | 게이트 |
|------|------|------|--------|
| **M0** | 범위·카피·색 토큰 확정 (위 질문) | 본 문서 §2 체크 | 사용자 합의 |
| **M1** | 목업 IA: 네비 + `memos.html` 셸 | 빈 보드 페이지 | 브라우저 확인 |
| **M2** | 스토어: `memos` CRUD + seed + persist | `mockups/js/store.js` | 새로고침 유지 |
| **M3** | 보드 UI: 추가·인라인 편집·색·삭제(모달) | `memos-page.js` + CSS | 컨펌 |
| **R1** | React 패리티: 타입·store·`/memos`·Layout | `src/` | 목업과 동일 동작 |
| **Q1** | 수동 QA: CRUD·영속·네비·초기화·a11y | 체크리스트 | 이슈 없으면 완료 |

**금지:** M3 컨펌 전 `src/` 대규모 구현 · 배포 티켓.

## 6. 티켓 초안 (백로그용)

### N1 · 메모 화면 셸 (목업)

**Outcome:** 상단 네비에 메모가 보이고, 보드 빈 상태가 뜬다.  
**Data:** 없음  
**Out:** CRUD  
**Accept:** 네비 5항목 · `aria-current` · 기존 페이지 네비에도 링크 추가

### N2 · 메모 스토어 (목업)

**Outcome:** 메모 추가·수정·삭제 후 새로고침해도 남는다.  
**Data:** `memos[]`  
**Out:** 드래그 좌표  
**Accept:** upsert/delete · seed 2~3장 · resetSeed에 포함

### N3 · 스티커 보드 UI (목업)

**Outcome:** 스티커처럼 보이며 색·본문 편집이 가능하다.  
**Data:** color, body  
**Out:** 리치 텍스트  
**Accept:** 추가 CTA · 빈 상태 · 삭제 확인 모달 · 모바일에서 1열~2열로 접힘

### N4 · React 패리티

**Outcome:** `/memos`가 목업과 동일하게 동작한다.  
**Data:** 동일 모델 · persist merge  
**Out:** 목업에 없는 기능  
**Accept:** 타입체크 통과 · 네비·CRUD·영속 수동 확인
