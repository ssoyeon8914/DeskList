# 작업 계획서 · 노트

**목적:** 폴더로 묶인 **긴 글·기록**을 DeskList에 두고, 일반 텍스트와 Markdown을 작성·저장하며 Markdown은 **프리뷰**까지 본다.  
**성격:** post-MVP · **목업 먼저** → 컨펌 → React 패리티  
**관련:** 메모(짧은 스티커)와 **역할 분리** · 엑셀 「설명서」급 기록 욕구 · 할일/달력과 비연동  
**비범위(이번 계획):** 배포, 서버 동기화, 실시간 협업, 이미지 업로드, 외부 파일 시스템 마운트, 할일·달력 자동 연동

---

## 1. 문제 · 성공 기준

| | |
|--|--|
| **지금** | 메모는 짧은 스티커용. 회의록·체크리스트·장문 기록·MD 초안을 둘 **기록 공간**이 없음 |
| **성공** | 상단 네비 **노트**에서 **폴더 → 제목 목록 → 본문** 3단으로 노트를 추가·수정·삭제하고, `.md`는 **좌우 분할** 편집|프리뷰가 되며 새로고침 후에도 **마지막 선택**이 유지된다 |
| **감성** | IDE·노션 복제물이 아니라 DeskList E+B 톤의 **차분한 기록실**. 3단 분할은 명확하되 슬롭 대시보드·과한 카드 스택 금지 |

**메모 vs 노트**

| | 메모 | 노트 (본 기능) |
|--|------|----------------|
| 단위 | 스티커 카드 | 폴더 안의 노트 |
| 길이 | 짧은 잡메모 (본문 ≤3,000자) | 장문 기록 (본문 ≤50,000자) |
| 형식 | 평문 + 색 | `text` / `markdown` + MD 좌우 프리뷰 |
| 레이아웃 | 보드 그리드 | **3단: 폴더 · 목록 · 편집기** |

## 2. 제품 결정 (확정)

### 2.1 In (v1)

- 상단 네비: **노트** (`/notes` · 목업 `notes.html`) — 메모와 설정 사이
- **3단 레이아웃**
  1. **왼쪽 — 폴더:** 폴더 목록 · 선택 · 추가·이름변경·삭제
  2. **가운데 — 제목 목록:** 선택 폴더의 노트 제목 · 추가·삭제 · 형식 뱃지(`txt`/`md`)
  3. **오른쪽 — 본문:** 선택 노트의 제목·본문 · Markdown일 때 **좌우 분할**(왼쪽 편집 | 오른쪽 프리뷰)
- 노트 형식: `text` | `markdown` (생성 시 선택, 이후 변경 가능하면 v1에 포함)
- Markdown 프리뷰: 제목·목록·굵게·링크·코드 블록 등 **안전한 서브셋** (XSS 방지 렌더)
- 본문 한도 **50,000자**
- **마지막 선택 기억:** `selectedFolderId` · `selectedDocId`를 persist에 저장 · 로드 시 복원(없으면 첫 폴더·첫 노트 또는 빈 상태)
- localStorage 영속 · 샘플 seed(폴더 1~2 + 노트 2~3) · 설정「샘플 초기화」에 포함
- 삭제 확인은 `DLModal` (native `alert`/`confirm` 금지)
  - **폴더 삭제:** 모달로 “폴더와 안의 노트 N개가 삭제됩니다” 승인 후에만 일괄 삭제
  - **노트 삭제:** 동일하게 확인 모달 후 삭제

### 2.2 Out (v1)

- 폴더 무한 중첩(트리 depth > 1) — v1은 **1단 폴더**만
- 드래그로 폴더 간 이동 / 정렬 커스텀(수동 정렬은 `updatedAt` 또는 제목순으로 충분)
- 첨부 파일·이미지 업로드·PDF export
- WYSIWYG / 블록 에디터 · 공동 편집
- 전체 검색·태그·즐겨찾기 핀 (v1.1 후보)
- 실제 디스크 `.md` 파일 I/O (앱 내 논리 문서만)
- 메모·할일·만다라트와 양방향 링크
- MD **탭 전환** UX (확정은 **좌우 분할**)

### 2.3 열어 둔 질문 → 확정 (2026-09-22)

| # | 질문 | 확정 |
|---|------|------|
| 1 | 네비 라벨 | **노트** |

## 3. 데이터 모델 (초안)

할일·메모 스토어와 **독립**.

```ts
type DocFormat = "text" | "markdown";

type DocFolder = {
  id: string;
  name: string;          // 폴더 표시명
  sort?: number;         // 선택 · 없으면 이름순
  updatedAt: string;     // ISO
};

type Doc = {
  id: string;
  folderId: string;      // DocFolder.id
  title: string;         // 가운데 목록·편집기 헤더
  format: DocFormat;     // text | markdown
  body: string;          // 원문 (md면 소스, text면 평문)
  updatedAt: string;     // ISO
};

type DocsUiState = {
  selectedFolderId: string | null;
  selectedDocId: string | null;
};

// AppState에
//   docFolders: DocFolder[]
//   docs: Doc[]
//   docsUi: DocsUiState   // 마지막 선택 기억
```

| 항목 | 규칙 |
|------|------|
| 소스 오브 트루스 | `state.docFolders` + `state.docs` |
| 파생 | 폴더별 목록 = `docs.filter(d => d.folderId === selectedFolderId)` |
| 영속 | desklist 키에 `docFolders`·`docs`·`docsUi` 병합 · 없으면 seed |
| 초기화 | `resetSeed` 시 샘플 폴더·노트 포함 · 선택 id 유효성 재검증 |
| 본문 한도 | `DOC_BODY_MAX = 50_000` · 제목 `DOC_TITLE_MAX` (예: 120) |
| MD 렌더 | 저장은 **항상 원문** · 프리뷰만 HTML 변환 (원문 오염 금지) |
| 선택 복원 | 저장된 id가 없으면 해당 폴더의 첫 노트 또는 null · 폴더도 없으면 null |

## 4. UX 스케치

```
[ DeskList ]  달력 · 할일 · 만다라트 · 메모 · 노트 · 설정
─────────────────────────────────────────────────────────────

┌──────────┬────────────────┬────────────────────────────────┐
│ 폴더     │ 노트           │  킥오프 메모          [md ▾]   │
│          │                │┌──────────────┬────────────────┐│
│ ▸ 회의   │  킥오프 메모   ││ # 제목       │ 제목(렌더)    ││
│   개인   │  주간 회고.md  ││ - 항목 …     │ • 항목 …      ││
│   아이디어│  촬영 체크리스트││ (textarea)   │ (preview)     ││
│          │                │└──────────────┴────────────────┘│
│ [+ 폴더] │ [+ 노트]       │  format=text 면 편집 전폭만     │
└──────────┴────────────────┴────────────────────────────────┘
```

- **왼쪽:** 폴더 클릭 → 가운데 목록 갱신 · 이름변경·삭제(삭제 시 **DLModal 승인**)
- **가운데:** 제목 클릭 → 오른쪽 로드 · `md`/`txt` 표시 · `+ 노트` 시 형식 선택
- **오른쪽 (markdown):** **좌우 분할** — 원문 편집 | 실시간(또는 짧은 디바운스) 프리뷰
- **오른쪽 (text):** 편집 영역 전폭 · 프리뷰 패널 없음
- **선택 기억:** 폴더/노트 클릭 시 `docsUi` 갱신 · 재방문 시 복원
- **빈 상태** (복원 실패·데이터 없음일 때만)
  - 폴더 없음: “폴더를 만들어 기록을 시작하세요”
  - 폴더만 있음: “이 폴더에 노트를 추가하세요”
- **반응형:** 좁은 폭에서는 3단 → 단계적 스택 · MD 분할도 상하로 접을 수 있음 — v1 목업에서 1안 확정
- **모션:** 패널 전환 1종 정도 · 과한 슬라이드 스택 금지

## 5. Markdown 프리뷰 (기술 메모)

| 항목 | 방침 |
|------|------|
| 파서 | 가벼운 MD→HTML (예: `marked` 또는 동등) · 목업도 동일 UX |
| 보안 | raw HTML 입력 허용 최소화 · `DOMPurify` 등으로 sanitize 후 삽입 |
| 지원 범위(v1) | ATX 제목, 문단, **굵게/기울임**, 목록, 링크, 인라인·펜스 코드, 인용 |
| 미지원(명시) | 스크립트, iframe, 임의 HTML 위젯 |
| text 형식 | 분할 프리뷰 숨김 · 편집만 |
| 갱신 | 입력 디바운스(예: 150–300ms)로 프리뷰 갱신 · 저장은 원문 |

라이브러리 확정은 **R1(React) 착수 시** eng 한 줄로 잠그고, 목업은 동일 서브셋이 보이게 CDN/번들로 맞춤.

## 7. 티켓 초안 (백로그용)

### D1 · 노트 화면 셸 (목업)

**Outcome:** 네비에 **노트**가 보이고, 3단 빈 레이아웃이 뜬다.  
**Data:** 없음  
**Out:** CRUD · MD  
**Accept:** 네비 라벨「노트」· `aria-current` · 기존 페이지 네비 동기화 · 3열 구조 식별 가능

### D2 · 폴더·노트 스토어 (목업)

**Outcome:** 폴더/노트 추가·수정·삭제 후 새로고침해도 남고, **마지막 선택**이 복원된다.  
**Data:** `docFolders[]`, `docs[]`, `docsUi`  
**Out:** 중첩 폴더 · 디스크 I/O  
**Accept:** upsert/delete · 폴더 삭제 시 자식 노트 제거 · seed · resetSeed · docsUi 유효성

### D3 · 3단 UI 연동 (목업)

**Outcome:** 폴더 선택 → 제목 목록 → 본문 편집이 한 흐름으로 된다.  
**Data:** selection + title/body  
**Out:** MD 분할 프리뷰  
**Accept:** 빈 상태 · **폴더/노트 삭제 DLModal 승인** · 자동 저장 · 선택 persist

### D4 · Markdown 좌우 분할 (목업)

**Outcome:** `markdown` 노트는 편집|프리뷰가 나란히 보이고 렌더가 갱신된다.  
**Data:** `format`, `body` 원문 유지  
**Out:** WYSIWYG · 탭 전환  
**Accept:** text는 전폭 편집 · 위험 HTML 미실행 · 샘플 md seed 1건

### D5 · React 패리티

**Outcome:** `/notes`가 목업과 동일하게 동작한다.  
**Data:** 동일 모델 · persist merge  
**Out:** 목업에 없는 기능  
**Accept:** 타입체크 통과 · 3단·CRUD·분할 MD·승인 삭제·선택 기억 수동 확인
